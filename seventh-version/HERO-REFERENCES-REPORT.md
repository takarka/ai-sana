## 1. blueyard.com — самая полезная архитектура

### 1.1 Один canvas на весь сайт

```
body.bg-background            background: #FFF6F4  (тёплый светлый!)
└─ div#__nuxt
   └─ canvas                  position: fixed; z-index: -1; 1512×806 CSS / 3024×1724 attr (DPR 2)
```

Не «canvas в hero», а **единственный фиксированный WebGL-слой под всей страницей**, `z-index: -1`. Весь контент — обычный DOM поверх. Сцена не пересоздаётся при переходе между секциями, а плавно меняет состояние. Это радикально дешевле, чем несколько canvas'ов, и даёт непрерывность: сфера, начатая в hero, продолжает расти на второй, третьей, четвёртой секции.

### 1.2 Скролл как камера

Hero: сфера едва выглядывает снизу, крупный заголовок сверху. Через ~10 тиков скролла сфера занимает пол-экрана, ещё через 25 — уходит за край, а поверх неё плывут карточки портфолио. Один непрерывный «долли» камеры, а не набор отдельных анимаций. Скролл сглажен Lenis.

### 1.3 Потематические CSS-переменные на секциях — берите обязательно

```css
:root {
  --gradient-computing:   linear-gradient(90deg, #6344d5, #7ba5e6, #bab8e4);
  --gradient-engineering: linear-gradient(90deg, #279cfb, #dae6e2, #ebd7ce);
  --gradient-biology:     linear-gradient(90deg, #19c9c9, #c2e7e0, #119898);
  --gradient-crypto:      linear-gradient(90deg, #af7fd2, #f9aab8, #ede8e9);
  --flag-computing: #babfff;  --flag-engineering: #bfe0f7;
  --flag-biology:   #8ceae4;  --flag-crypto:      #e3a2ef;
}
.gradient-computing { --section-gradient: var(--gradient-computing); --section-flag: var(--flag-computing); }
.gradient-biology   { --section-gradient: var(--gradient-biology);   --section-flag: var(--flag-biology); }
```

Секция несёт класс темы, дочерние элементы читают `var(--section-gradient)`. **Это ровно ваш паттерн `.band--ink` / `.band--paper`** (styles.css:111–127), только с большим числом тем. То есть вы уже строите систему правильно — можно расширить теми же средствами, без нового кода: `.band--course`, `.band--pisa`, `.band--analytics`, каждая переопределяет `--accent`.

### 1.4 Ещё: секции с `my-75vh`

Между смысловыми блоками — по 75vh воздуха. Именно это даёт скроллу «дыхание», за которое сцена успевает переехать. У вас сейчас `.band { padding: 12rem 0 }` — примерно 120px, в разы плотнее. Если пойдёте в scroll-driven сцену, воздух придётся добавить.

### 1.5 Прелоадер

Логотип в чёрном квадрате по центру + `003%` внизу моноширинным. Ваш `.pre` в `index.html` (счётчик `#prePct` + `AI`/`SANA` с растягивающимся баром) сделан по той же схеме — тут вы уже на уровне референса, менять нечего.

## 2. ricardochance.com — два приёма, которые можно взять сегодня

### 2.1 Пословная подсветка по скроллу — лучший «дешёвый» эффект из всех четырёх

Заголовок разбит на `<span>` по словам:

```html
<span>
  <span>Creating</span> <span>experiences</span> <span>that</span> <span>people</span> …
</span>
```

Слова стартуют приглушёнными (`≈#5A5468`), и по мере прокрутки последовательно переходят в яркий `#F5F4F8`. Ноль WebGL, ноль веса — а внимание держит лучше, чем частицы.

**У вас половина работы уже сделана**: в `app.js:326` есть `.js-split`, который режет `h1` на части. Добавить второй режим «по словам + scrub по скроллу» — 20–30 строк:

```css
.js-scrub span { color: var(--fg-dim); transition: color .35s var(--ease-out); }
.js-scrub span.is-lit { color: var(--fg); }
```

```js
/* в app.js, рядом с существующим IntersectionObserver */
document.querySelectorAll(".js-scrub").forEach(function (host) {
  var words = host.querySelectorAll("span");
  function onScroll() {
    var r = host.getBoundingClientRect();
    var p = 1 - (r.top - window.innerHeight * 0.15) / (window.innerHeight * 0.55);
    p = Math.max(0, Math.min(1, p));
    var n = Math.round(p * words.length);
    for (var i = 0; i < words.length; i++) words[i].classList.toggle("is-lit", i < n);
  }
  window.addEventListener("scroll", onScroll, { passive: true });
  onScroll();
});
```

Кандидаты в вашем контенте: `.lead` в hero, заголовок секции «Как устроена система», вводный абзац PISA-блока.

### 2.2 Рамка-уголки на весь вьюпорт

Тонкие уголковые скобки в четырёх углах экрана (`position: fixed`, цвет ≈`#3A2F4E` на фоне `#0D0718`). Мелочь, но задаёт «интерфейсность» — страница читается как прибор, а не как документ.

```css
.frame { position: fixed; inset: 2rem; pointer-events: none; z-index: 40; }
.frame::before, .frame::after { content: ""; position: absolute; width: 1.6rem; height: 1.6rem; border: 1px solid var(--line); }
.frame::before { top: 0; left: 0; border-right: 0; border-bottom: 0; }
.frame::after  { bottom: 0; right: 0; border-left: 0; border-top: 0; }
```

Отлично ложится на ваш `--ink-line: rgba(214,227,252,.14)` и на моноширинные микролейблы `.micro`.

### 2.3 Типографика

`Instrument Serif` italic 64px для display + гротеск для текста. Контраст «курсивная антиква / нейтральный санс» вытягивает совершенно пустую композицию. У вас Inter Tight + Onest + JetBrains Mono — три санса/моно, ни одной антиквы. **Не предлагаю менять** (ваш ТЗ-язык технологичный), но отмечу: их hero держится на этом контрасте, а не на 3D.

## 3. alche.studio — красиво, но брать почти нечего

Чёрный фон, всё нарисовано hairline-линиями: направляющие колонок, дуги, засечки, размерные линии. По мере скролла конструкция собирается в букву «A» — логотип студии. Моноширинный подзаголовок `Architect worlds that move hearts and spark hope.` держится в центре неподвижно.

Стек: three.js + GSAP + Lenis, единый `GLCanvas__container` (DPR 1.5), плюс **Tweakpane оставлен в проде** (`tp-svpv` в DOM) — то есть панель настройки шейдеров случайно уехала в релиз. Мелочь, но показательная.

Что применимо:
- **Идея «чертёж вместо иллюстрации»** — hairline-линии + моно-подписи вместо картинок. Это близко вашему `--ink-line` + `.micro` на JetBrains Mono, и это дешевле частиц.
- **Направляющие колонок как декор**: `Stellla__rect_line` — обычные `<div>` шириной 1px, `background: #999`, `position:absolute`. Не GL, просто DOM.

Что не применимо: сам сценарий «скролл собирает логотип» требует ручной покадровой режиссуры под конкретный знак. Для образовательной платформы с 8 разделами навигации это не окупится.

## 4. Сводная матрица приёмов

| Приём | Откуда | Цена | Эффект | Вердикт |
|---|---|---|---|---|
| Пословная подсветка по скроллу | ricardochance | ~30 строк JS/CSS | Высокий | **Делать первым** |
| Визуал, обрезанный краем секции + mask | maze | ~20 строк CSS | Высокий | **Делать** |
| HTML-пины, спроецированные из 3D | maze | средняя | Высокий (смысл!) | **Делать** |
| Потематические переменные на секциях | blueyard | у вас уже есть | Системный | **Расширить** |
| Рамка-уголки на вьюпорт | ricardochance | ~10 строк CSS | Средний | Делать |
| Один fixed canvas на весь сайт | blueyard | архитектурная | Высокий | Если пойдёте в WebGL — только так |
| Lenis (плавный скролл) | все три | +3 КБ | Средний | Опционально, но заметно |
| Воздух `my-75vh` между секциями | blueyard | верстка | Высокий при scroll-driven | Только вместе с WebGL |
| Hairline-чертёж как графика | alche | средняя | Средний | Рассмотреть вместо частиц |
| Контраст антиква-курсив / санс | ricardochance | шрифт | Высокий | Не берём (против ТЗ) |

| GSAP-стек из 5 плагинов | maze/все | +60 КБ | — | Нет, у вас свой рантайм |

**Общий знаменатель всех четырёх:** three.js + GSAP + Lenis. Ни у кого — Spline, Rive или готового генератора. Все рисуют сцену руками. И у всех canvas — это **фон**, а типографика и сетка несут смысл. Ни один из четырёх сайтов не «продаёт» 3D сам по себе.

## 5. Обновлённая рекомендация

Порядок из отчёта №1 остаётся, но я добавил бы нулевой шаг — он самый выгодный по соотношению «эффект / трудозатраты»:

**Шаг 0 (~1 час, ноль зависимостей).** Пословная подсветка `.js-scrub` на `.lead` в hero + рамка-уголки. Hero сразу перестаёт быть статичным, вес страницы не меняется. Приём ricardochance, работает и без WebGL, и при `prefers-reduced-motion` (просто все слова сразу яркие).

**Шаг 1.** CSS-слой `.hero__visual` — обрезанный краем, с mask-градиентом (приём Maze).

**Шаг 2.** HTML-пины с названиями курсов через `data-i18n` (приём Maze, но со смыслом вместо CVE).

**Шаг 3 (только если после 0–2 захочется большего).** WebGL — и тогда сразу по-blueyard'овски: **один `position:fixed; z-index:-1` canvas на всю страницу**, а не canvas внутри hero. Иначе при добавлении сцены во вторую секцию придётся всё переписывать. Порт `WebGLHeroScene` из `third-version/webgl-scene.js`, палитра — ваш `--signal-lift`.

Шаги 0–2 суммарно ~4 часа и полностью самодостаточны.
