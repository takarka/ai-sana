# MVP-0 CRAFT MATRIX: библиотека контента и автопроверяемые задания

**Задача.** Из всего объёма CRAFT MATRIX (раздел 6.2 ТЗ) выделить и зафиксировать
самый первый рабочий срез: то, что реально нужно учителю в первую очередь —
готовые уроки с материалами и заданиями, которые он раздаёт классу, и
результаты, которые видит без ручной проверки. Всё, что требует живой сессии
урока, светофора класса в реальном времени и симуляторов, — сознательно
отложено на следующий срез и здесь только перечислено, чтобы не потерялось.

**Смежные документы.**
[../tz/01-tz-platforma.md](../tz/01-tz-platforma.md) — источник требований
(`FR-CNT-*`, `FR-CMS-*`, `FR-MTX-*`, `FR-ASM-03`).
[02-moduli-matrix-builder-pisa.md](02-moduli-matrix-builder-pisa.md) — полная
раскладка MATRIX на backend-модули; этот документ сужает часть `Modules/Content`
и `Modules/Learning` до среза v0 (см. §5).
[05-kabinet-craft-web.md](05-kabinet-craft-web.md) — маршруты и контуры
кабинета; этот документ уточняет часть маршрутов контуров `learn` и `teach`
(см. §4).

**Результат этапа.** Учитель получает готовый урок с материалами, ученик
проходит урок и сдаёт задание, результат проверяется автоматически, учитель
видит по каждому ученику и по классу в целом: статус, балл, время выполнения.
Курс класса открыт ученику целиком — назначение уроков учителем отложено
(§4.2, решение от 12.09.2026).

**Что этот срез НЕ делает** (сознательно, см. §3): не ведёт живую сессию урока,
не считает светофор `green/yellow/red` в реальном времени, не запускает
симуляторы, не проверяет открытые ответы и проекты, не ставит дедлайны,
не формирует оценку F/P по ГОСО — только сырой балл и время.

## 1. Структура контента

Совпадает с иерархией [FR-CNT-01](../tz/01-tz-platforma.md#6-функциональные-требования)
без изменений — v0 не вводит новых сущностей, только сужает набор используемых
типов шага (§2) и функций вокруг них (§3).

```
Предмет «Цифровая грамотность и ИИ»  →  Модуль MATRIX (FR-CNT-01)
 └─ Класс (1…11)                     →  Курс = модуль + параллель
     └─ Раздел
         └─ Урок
             ├─ Материалы   — шаг типа `theory` (FR-CNT-02)
             │   ├─ видео
             │   ├─ текст
             │   ├─ изображение
             │   └─ файлы для скачивания
             └─ Задание(я)  — шаг(и) типа `task` (FR-CNT-02)
                 └─ Попытка ученика → результат, балл, время (FR-ASM-03)
```

Методичка и план урока — не отдельная сущность, а материал урока с областью
видимости «только учитель» (готовит почву для `FR-MTX-20`, полноценная печатная
версия — `FR-MTX-21` — уже вне v0, см. §3).

## 2. Типы заданий в v0

Только то, что проверяется машиной без участия учителя — точный список берётся
из [FR-CMS-02](../tz/01-tz-platforma.md#612-авторская-студия-content-studio),
без урезания:

| Тип | Пример |
|---|---|
| Одиночный выбор | Один правильный вариант из 4 |
| Множественный выбор | Несколько правильных вариантов |
| Соответствие | Сопоставить термин и определение |
| Упорядочивание | Расставить шаги алгоритма по порядку |
| Заполнение пропусков | Вписать слово/число в пропуск в тексте |
| Числовой ответ с допуском | Ответ `42 ± 0.5` |
| Короткий текстовый ответ | Проверка по эталону или regex |
| Перетаскивание | Разнести элементы по категориям (drag & drop) |

Свободный текстовый ответ без эталона, загрузка файла на проверку, проекты —
**вне v0**: их проверяет только человек, а ручной проверки в этом срезе нет
(`FR-ASM-03` отдельно оговаривает ручную проверку открытых ответов и проектов —
это следующий срез, не этот).

## 3. Явно отложено (не в v0)

Перечислено по ID, чтобы не потерялось при планировании следующего среза.

| Требование | Что это | Почему не сейчас |
|---|---|---|
| FR-MTX-10…19 | Сессия урока, дашборд учителя в реальном времени, светофор, тепловая карта, проекционный режим | Требует WebSocket-инфраструктуры и политики статуса ([план 02 §2.2](02-moduli-matrix-builder-pisa.md)) — отдельный, самый дорогой кусок MATRIX |
| FR-SIM-01…05 | Симуляторы | Отдельный контракт обёртки (iframe, sandbox-origin) — нечего показывать, пока нет самих симуляторов |
| FR-CNT-02 (`quiz`, `ai_practice`, `project`, `reflection`) | Остальные типы шага | `theory` и `task` закрывают материалы и автопроверку — этого достаточно для первого среза |
| FR-ASM-01/02/04 | Формативное/суммативное оценивание, перевод баллов в отметку, ручная корректировка | v0 показывает сырой балл `%`, а не оценку по шкале ГОСО |
| FR-MTX-06 (офлайн-очередь) | Автосохранение при обрыве связи | Нужна для полноценного плеера урока; для первой версии — отправка ответа целиком по кнопке «Сдать» |
| Дедлайны | Срок сдачи задания | Решение заказчика этой сессии: пока не ставим |
| FR-CMS-01 (визуальный редактор) | Полноценная авторская студия | См. открытый вопрос §7-О1 — чем наполняется контент до готового редактора |

## 4. Экраны и маршруты

Уточняет часть таблиц [плана 05 §3.2 и §3.3](05-kabinet-craft-web.md) — новые
строки и сужение уже перечисленных, остальные маршруты кабинета не меняются.

### 4.1. Контур `learn` (ученик)

Маршруты без префикса `/learn`: приложение развёрнуто на `learn.craftai.kz`
([ADR-0006](../adr/0006-domeny-i-marshruty-apps-learn.md)). Корень `/` —
главная ученика; курс живёт под `/matrix/**`
([ADR-0007](../adr/0007-glavnaya-i-prefiksy-moduley-learn.md),
[план 12](12-learn-navigatsiya-i-glavnaya.md)).

| Маршрут | Экран | Требования |
|---|---|---|
| `/matrix` | Курс: разделы → уроки | FR-CNT-01 (без изменений) |
| `/matrix/lessons/:lessonId` | Материалы урока (видео/текст/изображение/файлы) + список заданий урока | FR-CNT-02 (`theory`) |
| `/matrix/lessons/:lessonId/tasks/:taskId` | Прохождение одного задания, кнопка «Сдать» | FR-CMS-02, FR-ASM-03 |

`/matrix/courses/:courseId` зарезервирован на случай второго курса у класса
([план 12, К-22](12-learn-navigatsiya-i-glavnaya.md)). В v0 у класса один курс,
поэтому карта открывается сразу на `/matrix`.

В v0 нет пошагового плеера с прогресс-баром и подсказками — урок открывается
целиком, задания видны и доступны в любом порядке.

### 4.2. Контур `teach` (учитель)

| Маршрут | Экран | Требования |
|---|---|---|
| `/teach/classes/:classId` | Разделы и уроки курса класса: % класса выполнившего, средний балл | Сужение FR-MTX-22 — без отчёта покрытия ЦО |
| `/teach/classes/:classId/lessons/:lessonId/results` | Таблица: ученик × статус (не начал/в процессе/сдал) × балл × время | Новый экран v0, узкий срез FR-ASM-05 |
| `/teach/lessons/:lessonId/method-card` | Методичка и план урока (без печати A4 — FR-MTX-21 отдельно) | Сужение FR-MTX-20 |

**Назначения урока в v0 нет** (решение от 12.09.2026, меняет §7-О3 ниже):
весь курс класса доступен ученику сразу, как только у класса есть курс.
Маршрут `.../lessons/:lessonId/assign` и связанная с ним фича
`Curriculum/BuildAnnualPlan` (§5) откладываются вместе с КТП: они имеют смысл
там, где учитель управляет темпом класса по плану, а плана в v0 нет. Показатели
на экранах учителя считаются от факта прохождения, а не от момента назначения.

`/teach/classes/:classId/journal` из плана 05 (полный журнал F/P с
корректировкой оценки) в v0 не реализуется — его заменяет упрощённый
`.../results` выше.

## 5. Backend: что открывается в v0

Уточняет [план 02 §2.1–2.2](02-moduli-matrix-builder-pisa.md) — активна только
часть функций `Modules/Content` и `Modules/Learning`, без `Modules/Assessment`.

```
Content/Features/
└── MethodCards/
    └── GetMethodCard/            # методичка + план урока            FR-MTX-20 (без печати)

Learning/Features/StudentFlow/
├── SubmitAttempt/                 # ответ на задание → автопроверка   FR-CMS-02, FR-ASM-03
└── CompleteStep/                  # завершение урока (все задания сданы)
```

Не поднимаются в v0: `Authoring` (визуальный редактор — §7-О1),
`LessonSession/*` целиком, `Simulators/*`, весь `Modules/Assessment`.

Данные ложатся в уже описанные в [ТЗ §7.2](../tz/02-tz-nfr-i-priemka.md#72-основные-сущности)
сущности без изменения схемы: `course`/`section`/`lesson`/`step`, `task`,
`progress`, `attempt`. Поля `progress.статус-светофор` и `attempt.подсказки` в
v0 не заполняются — они уже есть в модели для следующего среза, а не выдумываются
заново, когда до него дойдёт очередь.

## 6. Прогресс по классу — что именно считаем

Один агрегат на двух уровнях, без отдельной аналитической сущности —
вычисляется по `progress`/`attempt` тех учеников, что зачислены в класс:

| Уровень | Что показываем |
|---|---|
| По уроку (`.../results`) | На каждого ученика: статус, балл (%), время выполнения |
| По классу (`/teach/classes/:classId`) | На каждый урок раздела: сколько из класса сдали (`14 / 22`), средний балл, среднее время |

### 6.1. Какую попытку считаем

Попытки не ограничены по умолчанию (§7-О5), а задания — закрытых типов с
автопроверкой. Значит ученик, который перебирает варианты, рано или поздно
получит 100 %, и средний балл класса по последней попытке перестанет что-либо
измерять. Поэтому фиксируются обе величины:

| Величина | Что означает | Где показываем |
|---|---|---|
| Балл **первой** попытки | Что ученик знал до того, как начал подбирать | Средний по классу считается по ней |
| **Лучший** балл | Дошёл ли ученик до верного ответа в итоге | Рядом с первым, в таблице результатов |
| Число попыток | Насколько дорого дался результат | Там же; три попытки на задание — сигнал учителю, а не нарушение |

Ученику показывается результат его последней попытки — он учится, а не сдаёт
экзамен.

Оба показателя — это существующий `GET /analytics/class/{id}`
([API §8.2 ТЗ](../tz/02-tz-nfr-i-priemka.md#82-ключевые-группы-эндпоинтов)) с
узким фильтром по курсу класса, а не новый эндпоинт.

## 7. Открытые вопросы

| № | Вопрос | Рекомендация |
|---|---|---|
| О1 | Кто и чем наполняет контент до готовой авторской студии (`FR-CMS-01` — вне v0)? | Минимальная форма создания урока (без визуального редактора, без предпросмотра) — только методисту/админу, отдельно от учительского интерфейса; полноценный Content Studio — по плану 02 §7 (очередь 1) |
| О2 | Обязательна ли привязка урока к ЦО ГОСО (`FR-CNT-03`) уже в v0? | Да, как обязательное поле при создании — иначе отчёт покрытия программы (следующий срез) придётся заполнять задним числом; но UI по ЦО в v0 не нужен, только сохранение кода |
| О3 | ~~«Назначить урок классу» — это отдельное действие учителя или урок автоматически доступен всем ученикам курса класса?~~ **Закрыт 12.09.2026** | Весь курс класса доступен ученику сразу; назначение делаем позже, вместе с КТП (§4.2). Прежняя рекомендация — отдельное действие «Назначить» — отменена решением заказчика |
| О5 | Сколько попыток у задания? | По умолчанию не ограничено. Ограничение задаёт методист платформы полем «максимум попыток» у задания в админке; учитель не переопределяет. Следствие для показателей — §6.1 |
| О4 | Видит ли ученик свой балл сразу после сдачи или только после того, как учитель «откроет» результаты? | Сразу — задание проверяется автоматически, скрывать нечего; открытые вопросы и ручная проверка (вне v0) — другой случай |
