# План работ: перенос лендинга `eighth-version/` в Angular (`apps/landing`)

**Задача.** Перенести публичный сайт `eighth-version/` (статический HTML/CSS/JS)
в `platform/front` как второе Nx-приложение `apps/landing` — Angular с
включённым SSR, официальной библиотекой `@angular/localize` для RU/KZ-перевода
вместо самодельного `js/i18n.js`, и вёрсткой на токенах дизайн-системы.

**Смежные документы.**
[01-bootstrap-platform.md](01-bootstrap-platform.md) — этот план предполагает,
что `platform/front` (Nx-воркспейс) уже создан по шагу 2 того плана; здесь
добавляется **второе** приложение в тот же воркспейс, `craft-web` не трогаем.
[03-design-system.md](03-design-system.md) — токены и компоненты, общие для
кабинета и лендинга, живут в `libs/shared/ui-tokens` и `libs/shared/ui`;
`landing` их переиспользует, а не заводит копию.
[ADR-0002](../adr/0002-frontend-stack-angular-tailwind.md) — стек фронтенда.
[ADR-0003](../adr/0003-landing-eighth-version-to-angular.md) — решение о переносе
и об удалении всех версий лендинга из root после cutover; закрывает открытый
вопрос L-1 (ниже оставлен как запись истории решения).
[ТЗ, FR-WEB-01…05](../tz/01-tz-platforma.md) — требования к публичному сайту,
FR-WEB-01 обновлён по [ADR-0003](../adr/0003-landing-eighth-version-to-angular.md).

**Результат этапа.** `apps/landing` в `platform/front` — Angular-приложение с
SSR, четырьмя маршрутами (главная, MATRIX, BUILDER, PISA), полным переносом
контента и визуальных эффектов `eighth-version/`, переводом на `@angular/localize`
(RU — исходный язык, KZ — вторая локаль) и токенами из `libs/shared/ui-tokens`.
Статический `eighth-version/` перестаёт быть источником правды для публичного
сайта; он и все более ранние версии лендинга в root удаляются из репозитория
на шаге 6 (cutover), после подтверждения `apps/landing` на проде — см.
[ADR-0003](../adr/0003-landing-eighth-version-to-angular.md).

**Что этот этап НЕ делает:** не меняет `craft-web` и кабинет; не реализует
CRM-бэкенд для формы «Запросить демо» (FR-WEB-02) — на этом этапе форма только
валидируется и складывается в очередь-заглушку, интеграция с CRM — отдельная
задача; не добавляет третий язык (английский) — только готовит архитектуру под
него (NFR-I18N-05).

## 2. Решения по стеку

| Решение | Значение | Обоснование |
|---|---|---|
| Приложение | второе Nx-приложение `landing` в существующем воркспейсе `platform/front` | Токены, ESLint-границы, CI-инфраструктура — общие с `craft-web`, дублировать воркспейс незачем |
| Генератор | `@nx/angular:application` с флагом SSR (`--ssr`) | Официальный Nx-генератор Angular-приложения с сервер-рендерингом «из коробки» |
| SSR | `@angular/ssr` (официальный пакет Angular), Express-сервер, гидратация (`provideClientHydration`) | Требование задачи; лендинг — публичная витрина, SEO и скорость первого рендера важны, в отличие от кабинета (см. 01-bootstrap-platform.md, п. 2.1: там SSR осознанно выключен) |
| Пререндер | точечно, для статических секций (`prerender` в конфиге SSR-билдера), где контент не персонализирован | Снижает нагрузку на Node-сервер; не отменяет SSR — используется как оптимизация поверх него, а не вместо |
| Перевод (i18n) | **`@angular/localize`** — официальная библиотека Angular | Прямое требование задачи («официальная библиотека ангулара для перевода»). Атрибуты `i18n` в шаблонах, извлечение строк `ng extract-i18n` → XLIFF, компиляция отдельных бандлов на каждую локаль |
| Локали | `ru` (source locale) + `kk-KZ` (перевод) | Соответствует существующему `js/i18n.js` (`ru`/`kz`) и NFR-I18N-01; архитектурно готово к третьему языку (NFR-I18N-05) добавлением локали в конфиг, без изменения кода |
| Роутинг локалей | `/ru/...` и `/kk/...` (`localize` billing в `angular.json`/`project.json`, `baseHref` на локаль) | Стандартный паттерн `@angular/localize`: каждая локаль — отдельный собранный бандл под своим префиксом. Лучше для SEO (индексируемые URL на каждый язык), чем текущее переключение без смены URL |
| Стили | Tailwind CSS v4 + `libs/shared/ui-tokens` | Тот же источник токенов, что и кабинет — см. [03-design-system.md, §4.5](03-design-system.md) |
| Тесты | Jest (unit) + Playwright (e2e, обе локали) | Совпадает с конвенцией `craft-web` |
| Хостинг SSR | Node-процесс (Express-сервер из `server.ts`) за реверс-прокси | Тот же паттерн, что для backend — уточняется в открытых вопросах (§7) |

### 2.1. Важное следствие выбора `@angular/localize`

В текущей реализации (`js/i18n.js`) язык переключается мгновенно, без перезагрузки
страницы (`applyTranslations()` по клику). `@angular/localize` — компиляция
**на этапе сборки**: переключение языка на лендинге станет переходом на другой
URL-префикс (`/ru/matrix` → `/kk/matrix`) с полной перезагрузкой страницы.

Это ожидаемое и допустимое поведение для витрины (в отличие от кабинета, где
`NFR-I18N-03` прямо запрещает потерю несохранённых данных при смене языка —
но это требование к `craft-web`, не к публичному сайту). Переключатель языка
(`.lang-btn`) на лендинге меняет `<a>`-ссылку на текущий путь в другой
локали, а не вызывает JS-функцию.

## 3. Инвентарь переноса контента

| Источник (`eighth-version/`) | Назначение в `apps/landing` |
|---|---|
| `index.html` | route `/` (`pages/home`) |
| `matrix.html` | route `/matrix` (`pages/matrix`) |
| `builder.html` | route `/builder` (`pages/builder`) |
| `pisa.html` | route `/pisa` (`pages/pisa`) |
| `styles.css` | разбирается на токены (→ `libs/shared/ui-tokens`, уже запланировано в 03-design-system.md) и компонентные стили страниц (→ `.scss` рядом с компонентами) |
| `js/core.js` | шапка, бургер-меню, модалка, аккордеон FAQ → Angular-компоненты в `app/shared/`, модалка — через Angular CDK `Overlay`/`Dialog` (тот же примитив, что и в `libs/shared/ui`, см. 03-design-system.md §5.1) |
| `js/i18n.js`, `js/lang/*.js` | **не переносится как код.** Ключи и переводы из словарей (`common.js`, `home.js`, `matrix.js`, `builder.js`, `pisa.js`) становятся источником для ручного переноса текста в шаблоны с атрибутами `i18n` (RU) и `messages.kz.xlf` (перевод) |
| `scene.js` (Three.js WebGL-сцена) | переносится как Angular-компонент, инициализация **только в браузере** (`afterNextRender` / `isPlatformBrowser`) — на сервере при SSR не выполняется |
| GSAP + ScrollTrigger (`matrix.html`) | аналогично: подключение и запуск только на клиенте, SSR отдаёт статичную разметку без анимации |
| Форма «Запросить демо» (FR-WEB-02) | Angular reactive form с валидацией; на этом этапе отправка — в очередь-заглушку (см. «Что этот этап НЕ делает») |
| Кнопка «Скачать презентацию» (FR-WEB-04) | статическая ссылка на PDF из `assets/`, версионирование через админку — не в этом этапе |

## 4. Пошаговый план

### Шаг 0. Предусловия

- [ ] `platform/front` уже создан (шаг 2 плана [01](01-bootstrap-platform.md)) и в нём есть `apps/craft-web`.
- [ ] Уточнить у заказчика конфликт с FR-WEB-01 (см. §7) до начала переноса контента —
      каркас приложения (шаги 1–2) можно готовить параллельно, перенос контента (шаг 3) — нет.

### Шаг 1. Генерация `apps/landing`

```bash
cd platform/front
npx nx g @nx/angular:application landing \
  --directory=apps/landing \
  --ssr=true \
  --style=scss \
  --standalone \
  --routing \
  --unitTestRunner=jest \
  --e2eTestRunner=playwright \
  --tags=type:app,scope:landing
```

> Точный набор флагов сверить с `npx nx g @nx/angular:application --help` на
> фактической версии Nx (см. таблицу версий в [01-bootstrap-platform.md, §2.3](01-bootstrap-platform.md)).

- [ ] Проверить, что сгенерирован `server.ts` (Express) и таргет `serve-ssr`/`serve-static` в `project.json`.
- [ ] Подключить `libs/shared/ui-tokens` (Tailwind `@theme`, шрифты) — так же, как в `craft-web`.
- [ ] Убрать демо-контент со стартовой страницы генератора.

**DoD:**
```bash
npx nx build landing        # клиентский и серверный бандлы собираются
npx nx serve landing        # SSR-сервер поднимается, HTML приходит с сервера (view-source без пустого <app-root>)
```

### Шаг 2. `@angular/localize` и локали

```bash
npx nx g @angular/localize:init landing   # либо `ng add @angular/localize` в контексте проекта
```

- [ ] В `project.json` / `angular.json` прописать `i18n.sourceLocale: "ru"` и `i18n.locales.kk-KZ`.
- [ ] `npx nx run landing:extract-i18n` → `src/locale/messages.xlf` (источник RU).
- [ ] Скопировать в `messages.kk-KZ.xlf`, перенести переводы из `js/lang/*.js` (маппинг — таблица §3).
- [ ] Настроить билд на обе локали (два бандла, `/ru` и `/kk`, `baseHref` на локаль).
- [ ] Редирект с `/` на локаль по `Accept-Language` (или на `ru` по умолчанию) — в `server.ts` или на уровне реверс-прокси (см. открытый вопрос §7).
- [ ] Переключатель языка (`app/shared/lang-switcher`) — ссылки на текущий путь в другой локали, `hreflang` в `<head>` на обеих версиях страницы.

**DoD:** `npx nx build landing --localize` собирает `dist/apps/landing/browser/{ru,kk-KZ}` и соответствующие серверные бандлы; страница на `/kk/...` отдаёт переведённый HTML без JS (view-source).

### Шаг 3. Перенос контента и компонентов

- [ ] Компонент шапки/футера/бургер-меню (`app/shared/header`, `.../footer`) — из `core.js`.
- [ ] Модалка на Angular CDK `Dialog` — сохранить контракт доступности лендинга (focus trap, `inert`, Escape, возврат фокуса — уже реализовано и проверено в `core.js`, компонент из `libs/shared/ui` при наличии, см. 03-design-system.md §4.1).
- [ ] Аккордеон FAQ — ARIA-разметка как на лендинге.
- [ ] Четыре страницы-маршрута (`home`, `matrix`, `builder`, `pisa`) — верстка на Tailwind-утилитах поверх токенов, тексты — под `i18n`-атрибутами.
- [ ] WebGL-сцена (`scene.js`) и GSAP-сценарий (`matrix.html`) — client-only инициализация, `prefers-reduced-motion` уважается (как и в дизайн-системе кабинета, 03-design-system.md §3.3/§5.2).
- [ ] Форма «Запросить демо» — reactive form, клиентская и серверная валидация полей (ФИО, школа, e-mail, телефон), защита от спама (honeypot-поле минимум) — см. FR-WEB-02.
- [ ] Meta-теги (`Title`, `Meta` из `@angular/platform-browser`) на каждый маршрут и на каждую локаль; `sitemap.xml` и `robots.txt` в `public/`.

**DoD:** все четыре страницы визуально и функционально эквивалентны текущему `eighth-version/` (ручное сравнение бок о бок + Playwright-скриншоты); Lighthouse SEO ≥ 95 на обеих локалях.

### Шаг 4. Доступность и качество

- [ ] axe без нарушений уровня A/AA на всех четырёх страницах, обеих локалях.
- [ ] Клавиатурная навигация (Tab-порядок, фокус-видимость) — ручной прогон.
- [ ] Playwright e2e: переключение языка, отправка формы демо, открытие/закрытие модалки, работа при масштабе 200%.
- [ ] Бюджет производительности: проверить, что WebGL-сцена не блокирует TTI (ленивая инициализация после первого рендера).

### Шаг 5. CI

- [ ] `.github/workflows/platform-front.yml` (или отдельный workflow) расширяется на `nx affected -t lint,test,build` для `landing`.
- [ ] Отдельный e2e-джоб Playwright на `landing` (обе локали).
- [ ] Lighthouse CI на `/ru` и `/kk` с порогом по SEO/Performance/Accessibility.

**DoD:** пайплайн зелёный на pull request, затрагивающем `apps/landing`.

### Шаг 6. Точка перехода (cutover) и удаление старых версий лендинга

- [ ] `apps/landing` разворачивается на стейджинге, параллельно с текущим статическим `eighth-version/`.
- [ ] Сверка контента и форм с заказчиком/методистом.
- [ ] Убедиться, что весь нужный материал уже перенесён: токены и обоснование контраста
      из `eighth-version/DESIGN.md` — в [03-design-system.md](03-design-system.md);
      переводы из `js/lang/*.js` и `*/i18n.js` каждой версии — в `apps/landing/src/locale/*.xlf`
      (см. §3 выше). После шага 6 эти файлы недоступны иначе, чем через git-историю.
- [ ] Домен/прокси переключается на SSR-сервер `landing`.
- [ ] Удалить из root **все** версии лендинга, по решению [ADR-0003](../adr/0003-landing-eighth-version-to-angular.md):
  - [ ] папки `second-version/`, `third-version/`, `fourth-version/`, `fifth-version/`,
        `sixth-version/`, `seventh-version/`, `eighth-version/`;
  - [ ] лендинг-файлы без версии прямо в root: `index.html`, `app.js`, `styles.css`, `i18n.js`, `hero-1440.png`.
  - [ ] `requrement` (исходное текстовое ТЗ на лендинг) — не версия сайта, а документ;
        оставить в root либо перенести в `docs/`, решение — отдельным мелким коммитом,
        не блокирует cutover.
- [ ] Один коммит `chore(landing): remove legacy landing versions, superseded by apps/landing`
      — не смешивать с кодовыми изменениями `apps/landing`.

**DoD:** публичный сайт обслуживается `apps/landing`; в root не осталось ни
`eighth-version/`, ни более ранних версий (`second-version` … `seventh-version`),
ни лендинг-файлов без версии; `git log` по удалённым путям сохраняет историю.

| Что | Правило |

| Компоненты | Standalone, `OnPush`, сигналы — как в `craft-web` (01-bootstrap-platform.md, §5) |

## 6. Definition of Done этапа

1. `apps/landing` собирается, проходит `lint`/`test`/`build` для обеих локалей.
2. SSR отдаёт полностью отрендеренный HTML (проверено view-source, без JS).
3. Контент всех четырёх страниц перенесён и эквивалентен `eighth-version/`.
4. Перевод — через `@angular/localize`, ключи `js/lang/*.js` перенесены в XLIFF, ни одной строки мимо `i18n`.
5. axe (A/AA) и Playwright e2e — зелёные на обеих локалях.
6. CI-пайплайн для `landing` зелёный на pull request.
7. Cutover выполнен: прод обслуживается `apps/landing`; `eighth-version/` и все
   более ранние версии лендинга удалены из root (ADR-0003).

**Оценка трудоёмкости:** 8–12 рабочих дней для одного фронтенд-инженера — перенос
четырёх страниц с WebGL/GSAP-эффектами и двуязычным SSR ощутимо больше, чем
пустой каркас `craft-web` (01-bootstrap-platform.md давал 3–5 дней на голый скелет
без контента).
