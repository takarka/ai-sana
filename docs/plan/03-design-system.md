# Дизайн-система рабочего кабинета CRAFT AI

Дополнение к [плану инициализации](01-bootstrap-platform.md). В самом плане
дизайн-система была упомянута двумя строками («SCSS», `libs/shared/ui`) — этого
недостаточно, чтобы её кто-то построил. Документ закрывает пробел.

**Требование заказчика:** кабинет должен выглядеть так же, как лендинг
`eighth-version`. Оно принимается: бренд-слой переносится целиком и становится
единственным источником правды. Ниже — что именно переносится, что обязано
измениться и почему.

---

## 1. Почему кабинет не может быть копией лендинга 1:1

Лендинг и кабинет решают разные задачи, и это меняет не бренд, а режим подачи:

| | Лендинг `eighth-version` | Кабинет платформы |
|---|---|---|
| Сессия пользователя | 2–3 минуты, один раз | 45 минут урока, каждый день, 5 лет |
| Задача | Убедить директора | Не мешать учителю работать |
| Плотность | `--band-air: 12rem`, текст 1.7rem | Таблица на 35 учеников должна помещаться на экран |
| Устройство | Ноутбук директора | Школьный ПК 4 ГБ, канал 2 Мбит/с на класс |
| Что допустимо | WebGL-сфера, GSAP-скраб, скролл-сценарии | Ничего, что тратит кадры на анимацию вместо отклика |

Поэтому правило такое: **бренд-слой (цвет, типографика, семантика) переносится
без изменений, слой подачи (плотность, воздух, моторика) переопределяется.**
Кабинет остаётся узнаваемо тем же продуктом, но перестаёт быть презентацией.

## 2. Что переносится из `eighth-version` без изменений

### 2.1. Цветовые токены

Берутся из `eighth-version/styles.css` целиком, включая уже посчитанные контрасты
из [`DESIGN.md`](../../eighth-version/DESIGN.md):

```css
/* сцена */            --ink-900 #04060F  --ink-800 #0A0E1C  --ink-700 #131A2E
/* бумага */           --paper #F4F6FB    --card #FFFFFF     --paper-line #DDE3F0
/* ядро CRAFT AI */    --brand #0004EB    --brand-lift #7E8BFF
/* MATRIX */           --m-matrix #0047BA --m-matrix-lift #58B2FF
/* BUILDER */          --m-builder #5B16D0 --m-builder-lift #A78BFA
/* PISA */             --m-pisa #006C59   --m-pisa-lift #2DD4BF
/* текст */            --on-ink #D6E3FC   --on-paper #0A0E1C  + *-dim
/* статусы (paper) */  --lvl-high #1B9E6B --lvl-mid #D9902B  --lvl-low #D0503C
/* статусы (ink)   */  --lvl-high-ink #2ED573 --lvl-mid-ink #FFA502 --lvl-low-ink #FF4757
```

Все восемь модульных значений уже проверены на WCAG AA (от 6.4:1 до 10.9:1) —
пересчитывать не нужно, нужно не сломать.

### 2.2. Механизм модульных тем

На лендинге тема переключается классом на `<body>`: `page--matrix`,
`page--builder`, `page--pisa` переопределяют `--signal`, `--signal-lift`,
`--signal-wash`. В кабинете тот же приём, но на контейнере маршрута:

```html
<div class="app-shell" data-module="matrix">   <!-- синий -->
<div class="app-shell" data-module="builder">  <!-- фиолетовый -->
<div class="app-shell" data-module="pisa">     <!-- бирюзовый -->
```

Ученик переходит из урока MATRIX в тренажёр PISA — и акцент меняется вместе с
разделом. Это единственная вещь, которая на лендинге и в кабинете работает
буквально одинаково.

### 2.3. Три типографических голоса

| Голос | Шрифт | Где |
|---|---|---|
| Display | Inter Tight 600/800 | Заголовки экранов, крупные числа в дашборде |
| Body | Onest 400/500/600/700 | Основной текст, теория урока, таблицы |
| Micro / UI | JetBrains Mono 400/500/600 | Статусы, таймеры, метки, коды ЦО, кнопки-чипсы |

Все три поддерживают расширенную кириллицу (Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І) —
это уже проверено на лендинге и является требованием `NFR-I18N-01`.

### 2.4. Семантика статусов

`--lvl-high/mid/low` — зелёный/жёлтый/красный светофор ученика (`FR-MTX-12`).
Вместе с ним переносится главное правило лендинга: **статус кодируется не
цветом, а цветом + иконкой + текстом** (`FR-MTX-17`, `NFR-A11Y-03`). На лендинге
это `.desk-badge::before` плюс подпись — в кабинете тот же контракт компонента.

### 2.5. Геометрия и корневой размер

`html { font-size: 62.5% }` (1rem = 10px), `--r-card: 1.6rem`, `--r-chip: .6rem`,
`--r-pill: 10rem`, `--ease-signal`, `--ease-out` — переносятся как есть.

## 3. Что обязано измениться

### 3.1. Плотность вместо воздуха

Лендинг дышит: `--band-air: 12rem` между секциями, `--wrap: 132rem`, базовый
текст 1.7rem. В кабинете это означало бы, что дашборд класса из 35 строк не
помещается на экран, и учитель во время урока скроллит вместо того, чтобы
смотреть.

Вводится шкала плотности — тремя значениями, а не свободными числами:

```css
[data-density="comfortable"] { --row-h: 5.6rem; --gap: 2.4rem; --fs-base: 1.6rem; }
[data-density="compact"]     { --row-h: 4.4rem; --gap: 1.6rem; --fs-base: 1.5rem; }
[data-density="junior"]      { --row-h: 7.2rem; --gap: 3.2rem; --fs-base: 2.0rem; }
```

`junior` — не «крупнее для красоты», а требование `FR-MTX-05`: для 1–4 классов
крупные элементы, минимум текста, игровые метафоры. Плотность выбирается
автоматически по параллели ученика и переопределяется вручную учителем.

### 3.2. Бумага по умолчанию, сцена — точечно

Лендинг чередует полосы `band--ink` (тёмная сцена) и `band--paper`. Кабинет
работает на `--paper` постоянно: пять часов подряд читать светлый текст на
`#04060F` утомительно, а печать отчётов с тёмного фона невозможна.

Тёмная сцена остаётся ровно в двух местах, где она уже отработана на лендинге:

- **дашборд учителя** — на лендинге он и так лежит на `band--ink`, и для него уже
  есть яркая версия статусов `--lvl-*-ink`;
- **проекционный режим** (`FR-MTX-19`) — обезличенный дашборд на интерактивной
  доске, где тёмный фон читается лучше при включённом свете.

### 3.3. Что не переносится совсем

| Что | Почему |
|---|---|
| WebGL-сцена (`scene.js`, Three.js) | `NFR-NET-06`: облегчённый режим для школьных ПК. На экране, где учитель ищет отстающего ученика, вращающаяся сфера — помеха |
| GSAP + ScrollTrigger | На лендинге подключён только на `matrix.html` ради скролл-сценария. В кабинете скролл-сценариев нет |
| Прелоадер | Оправдан для витрины, в рабочем инструменте — потерянная секунда на каждом переходе |
| `clamp()` с `vw` в типографике | При масштабе 200 % (`NFR-A11Y-06`) `vw`-размеры не растут вместе с текстом. В кабинете — фиксированная rem-шкала |
| Заголовки Inter Tight 800 UPPER | Капслок кириллицы плохо читается в длинных строках, особенно с казахскими глифами. Остаётся для крупных чисел и коротких меток, а не для заголовков экранов |

### 3.4. Шрифты — самостоятельный хостинг

Лендинг грузит Inter Tight, JetBrains Mono и Onest с `fonts.googleapis.com`.
Для кабинета это не годится: школьные сети фильтруют внешние домены, а падение
CDN оставит учителя без интерфейса посреди урока.

Шрифты кладутся в `libs/shared/ui-tokens/assets/fonts`, подключаются локально
через `@font-face` с `font-display: swap`, только нужные начертания и только
подмножества `cyrillic`, `cyrillic-ext`, `latin`. Это же экономит трафик по
`NFR-NET-05` (≤ 20 МБ на урок).

## 4. Инвентарь компонентов

Того, что есть на лендинге, для кабинета мало: там нет ни одной таблицы данных,
формы с валидацией и состояния загрузки. Список ниже — минимальный набор `v1`.

### 4.1. Переносится с лендинга

| Компонент | Источник | Что уже готово |
|---|---|---|
| Кнопки (primary / ghost / pill) | `.btn`, `.btn--*` | Стили, состояния, фокус |
| Чипсы и метки | `.chip` | Моноширинный голос |
| Модальное окно | `#modal` в `core.js` | Focus trap, `inert` на фоне, возврат фокуса, Escape — редкая полностью доступная реализация, переносится по контракту |
| Аккордеон | FAQ на главной | ARIA-разметка |
| Бейдж статуса | `.desk-badge` | Цвет + иконка + текст |
| Таблица дашборда | `#desk` | Разметка и фильтры-заготовки |
| Шапка и бургер | `core.js` | Порог 1180px, клавиатура |

### 4.2. Создаётся заново

| Группа | Компоненты |
|---|---|
| Данные | Таблица с сортировкой, фильтрами и виртуализацией (35+ строк, обновление ≤ 5 с); пагинация; пустое состояние; скелетон загрузки |
| Формы | Поле, селект, чекбокс, радио, дата, файл; сообщение об ошибке; блок валидации формы; автосохранение с индикатором |
| Обучение | Карточка шага урока; навигация по шагам; блок теории; обёртка симулятора (`FR-SIM-01`); панель подсказок; результат попытки с разбором ошибки |
| Дашборд | Строка ученика со светофором; тепловая карта шагов; карточка «нужна помощь»; сводка урока; счётчик времени урока |
| Оценивание | Рубрика; поле дескрипторов F/P; журнал класса; корректировка оценки с причиной |
| PISA | Таймер среза; прогресс по блокам; карточка составного задания (стимул + вопросы); уровень по шкале; тепловая карта рисков |
| BUILDER | Конструктор промпта (блоки-чипсы); индикатор качества промпта; обёртка песочницы (`iframe`, отдельный origin); лента итераций; карточка портфолио |
| Графики | Динамика по срезам, распределение по уровням, сравнение параллелей |
| Служебные | Тост-уведомление; подтверждение действия; индикатор «нет связи, работа сохранена» (`NFR-NET-02`); переключатель языка RU/KZ; переключатель плотности |

### 4.3. Графики рисуются своими SVG-компонентами

На лендинге графики динамики готовности PISA нарисованы вручную в
`page-pisa.js` — и это правильный выбор, который переносится в кабинет.
Библиотека вроде Chart.js или ECharts добавит 150–250 КБ к бандлу при лимите
300 КБ (`NFR-PRF-07`) и приведёт свою палитру, которую придётся перебивать.

Типов графиков в `v1` всего четыре: столбцы, линия динамики, распределение по
уровням, тепловая карта. Все четыре — статические SVG на данных с сервера,
без анимации и интерактива сверх подсказки при наведении.

## 5. Где это живёт в Nx

```
platform/front/libs/shared/
├── ui-tokens/                      # без единого TS-файла
│   ├── src/tokens/
│   │   ├── _color.scss             # ← копия токенов eighth-version + токены кабинета
│   │   ├── _typography.scss        # три голоса, шкала размеров
│   │   ├── _density.scss           # comfortable / compact / junior
│   │   ├── _geometry.scss          # радиусы, тени, сетка
│   │   └── _motion.scss            # ease-функции, длительности
│   ├── src/base/
│   │   ├── _reset.scss
│   │   ├── _fonts.scss             # локальные @font-face
│   │   └── _a11y.scss              # фокус, skip-link, sr-only
│   └── assets/fonts/               # self-hosted woff2
└── ui/                             # компоненты
    ├── src/lib/button/
    ├── src/lib/data-table/
    ├── src/lib/status-badge/
    ├── src/lib/modal/
    └── …
```

### 5.1. Свои компоненты на Angular CDK, не Angular Material

Material принесёт готовые доступные компоненты — и вместе с ними Material
Design: свои радиусы, тени, ripple, типографику и палитру. Перебивать это под
бренд CRAFT AI дороже, чем собрать компоненты самим.

Рекомендация: **Angular CDK без Material-темы.** CDK даёт именно те примитивы,
которые тяжело и опасно писать вручную — `Overlay`, `FocusTrap`,
`LiveAnnouncer`, `a11y`, виртуальный скролл для таблицы, drag-drop для
авторской студии, — и не навязывает ни одного пикселя внешнего вида.

### 5.2. Правила, которые проверяются автоматически

| Правило | Как проверяется |
|---|---|
| В компонентах нет hex-цветов, только `var(--…)` | Stylelint: `color-no-hex` вне `ui-tokens` |
| Контраст текста ≥ 4.5:1, элементов ≥ 3:1 | Скрипт-валидатор палитры в CI + axe на ключевых экранах |
| Статус не кодируется одним цветом | Ревью + тест: `status-badge` рендерит текст и иконку всегда |
| Фокус виден на всех интерактивных элементах | axe + ручной прогон по клавиатуре |
| Работает при масштабе 200 % без горизонтального скролла | Playwright-тест на ключевых экранах |
| `prefers-reduced-motion` отключает анимации | Unit-тест на утилиту моторики |

### 5.3. Storybook

Каждый компонент — со сценариями: светлая и тёмная поверхность, три плотности,
RU и KZ (казахский текст длиннее русского на 10–20 % и первым ломает вёрстку),
состояния загрузки/ошибки/пустоты. Storybook — это же и площадка приёмки
дизайна методистами до того, как компонент попадёт в экран.

## 6. Что добавляется в план инициализации

Новый **шаг 2.5**, между Nx-workspace и backend:

- [ ] Создать `libs/shared/ui-tokens`: перенести токены из `eighth-version/styles.css`, добавить шкалу плотности.
- [ ] Скачать и положить шрифты локально, настроить `@font-face` с подмножествами кириллицы.
- [ ] Создать `libs/shared/ui` и подключить Angular CDK.
- [ ] Реализовать три компонента-эталона: `button`, `status-badge`, `data-table` — они задают правила для остальных.
- [ ] Поднять Storybook, добавить сценарии RU/KZ и трёх плотностей.
- [ ] Подключить Stylelint с запретом hex вне `ui-tokens`.
- [ ] Собрать демо-страницу «все токены и компоненты» для приёмки дизайнером и методистом.

**DoD шага:** `nx run shared-ui:storybook` открывается; три эталонных компонента
проходят axe без нарушений уровня A и AA; переключение `data-module` меняет
акцент на всех трёх; переключение `data-density` меняет высоту строки таблицы.

**Оценка:** 4–6 рабочих дней дизайнера и фронтенд-разработчика вместе. Это
больше, чем на генерацию обоих проектов (полдня), и такой порядок правильный:
дизайн-система, собранная после двадцати экранов, всегда собирается заново.

## 7. Открытые вопросы

| № | Вопрос | Рекомендация |
|---|---|---|
| D-1 | Нужна ли тёмная тема кабинета целиком (не только дашборд)? | Не в `v1`. Токены двухслойные, добавить позже дёшево; поддерживать две темы на 60 экранах сразу — дорого |
| D-2 | Angular CDK или Angular Material? | CDK без Material-темы (см. 5.1) |
| D-3 | Кто владелец дизайн-системы после этапа 0? | Назначить одного человека: без владельца библиотека расползается на 20 вариантов кнопки |
| D-4 | Обновлять ли `eighth-version` при изменении токенов? | Да, но односторонне: источник правды — `ui-tokens`, лендинг синхронизируется вручную при изменении палитры. Автоматическую связку не строить — лендинг бессборочный |
| D-5 | Нужны ли иллюстрации и маскот для 1–4 классов? | Отдельная задача дизайнера, не входит в этап. Заложить место в макетах `junior`-плотности |
