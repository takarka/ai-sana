# MVP-0 CRAFT PISA: только тренажёры

**Задача.** Из всего объёма CRAFT PISA (раздел 6.4 ТЗ) выделить первый рабочий
срез — так же, как это сделано для MATRIX в
[06-matrix-mvp0-kontent-i-zadania.md](06-matrix-mvp0-kontent-i-zadania.md).
В этот срез входит только раздел «Банк заданий и тренажёры» (ТЗ §6.4.1):
ученик свободно тренируется, банк заданий пополняется методистами платформы.
Срезы (экзаменационный режим) и управленческий дашборд — решением этой сессии
отложены целиком, до появления самих тренажёров с достаточным банком заданий.

**Смежные документы.**
[../tz/01-tz-platforma.md](../tz/01-tz-platforma.md) — источник требований
(`FR-PSA-*`).
[02-moduli-matrix-builder-pisa.md](02-moduli-matrix-builder-pisa.md) — полная
раскладка `Modules/Pisa` на backend-фичи; этот документ сужает часть
`ItemBank` и `Trainers` до среза v0 (см. §4).
[05-kabinet-craft-web.md](05-kabinet-craft-web.md) — маршруты кабинета; этот
документ уточняет часть маршрутов контура `learn` и снимает на время v0
маршруты `teach`/`manage`, относящиеся к PISA (см. §3).
[06-matrix-mvp0-kontent-i-zadania.md](06-matrix-mvp0-kontent-i-zadania.md) —
тот же формат сужения и тот же общий движок закрытых типов вопросов
(FR-CMS-02), которым тренажёры пользуются, а не изобретают свой.

**Результат этапа.** Ученик в любой момент открывает тренажёр по одному из
трёх направлений грамотности, решает составное задание (стимул + вопросы),
получает вместо простого вердикта разбор ошибки и подсказки, и видит свою
личную статистику по направлениям.

**Что этот срез НЕ делает:** не проводит срезы (планирование, индивидуальные
варианты, таймер, антисписывание), не считает готовность класса/параллели,
не строит управленческий дашборд и отчёты для УоО, не включает спецмодуль
«Медиа- и ИИ-грамотность» (это следующий шаг после базовых трёх направлений —
решение этой сессии), не показывает учителю и администрации никакой сводки по
тренажёрам — вообще никакой педагогической или управленческой поверхности,
кроме личной статистики самого ученика.

---

## 1. Что входит в v0

| Требование | Что это |
|---|---|
| FR-PSA-02 | Тренажёры по трём направлениям: математическая, естественно-научная, читательская грамотность |
| FR-PSA-05 | Составное задание: один стимул (текст/график/источники) + несколько вопросов разных форматов |
| FR-PSA-04 | Автоматический разбор решения: не «верно/неверно», а объяснение ошибки и пошаговые подсказки |
| FR-PSA-06 | Метаданные задания: направление, когнитивный процесс, контекст, уровень по шкале, время выполнения |
| FR-PSA-01 | Банк заданий собственной разработки методистов платформы, с автором и датой; полнотекстовый поиск и фильтры |

Вопросы внутри составного задания используют тот же закрытый набор типов, что
уже утверждён для автопроверяемых заданий MATRIX
([план 06 §2](06-matrix-mvp0-kontent-i-zadania.md#2-типы-заданий-в-v0),
источник — FR-CMS-02): движок «показать вопрос → принять ответ → проверить»
общий, PISA его не переизобретает (та же логика разделения, что в
[плане 02 §4.1](02-moduli-matrix-builder-pisa.md#41-почему-pisa-отделена-от-assessment)).

## 2. Явно отложено

| Требование | Что это | Почему не сейчас |
|---|---|---|
| FR-PSA-03 | Спецмодуль «Медиа- и ИИ-грамотность» | Решение этой сессии: отдельным шагом после трёх базовых направлений — контентно тяжелее (фейки/дипфейки, мультимодальные источники) |
| FR-PSA-07 | Адаптивный подбор задания по уровню ученика | `S`-приоритет, нужен ADR по модели (IRT vs пороговая логика); без него тренажёр просто предлагает задания по выбранному направлению и уровню вручную |
| FR-PSA-10…14 | Срезы: планирование, индивидуальные варианты, таймер, автосдача, антисписывание | Экзаменационный режим — решением этой сессии не в v0; тренажёр не запрещает повтор задания и не ограничивает время |
| FR-PSA-20…25 | Управленческий дашборд, тепловая карта рисков, отчёты для УоО, прогноз баллов | Данных для расчёта готовности просто ещё нет — они появляются только из срезов |
| — | Любой отчёт/сводка для учителя, завуча, методиста по тренажёрам | Решение этой сессии: в v0 это исключительно ученический инструмент |

## 3. Экраны и маршруты

Уточняет [план 05 §3.2](05-kabinet-craft-web.md#32-контур-learn-ученик):
маршрут тренажёров сохраняется, срез — убирается из v0; и снимает на время
v0 два маршрута контуров `teach`/`manage`, которые план 05 закладывал под
полную версию PISA.

### 3.1. Контур `learn` (ученик) — доступ свободный, без назначения учителем

| Маршрут | Экран | Требования |
|---|---|---|
| `/learn/pisa` | Выбор направления: математическая / естественно-научная / читательская грамотность | FR-PSA-02 |
| `/learn/pisa/:direction` | Список доступных заданий направления с фильтром по уровню | FR-PSA-01, FR-PSA-06 |
| `/learn/pisa/:direction/items/:itemId` | Составное задание: стимул + вопросы | FR-PSA-05 |
| `/learn/pisa/:direction/items/:itemId/result` | Результат попытки: балл, разбор ошибки, подсказки | FR-PSA-04 |
| `/learn/pisa/stats` | Личная статистика: решено заданий, средний балл и уровень по каждому направлению | Новое в v0 — не было отдельным экраном ни в ТЗ, ни в плане 05 |

`/learn/pisa/runs/:runId` из плана 05 (прохождение среза с таймером) в v0 не
реализуется — вернётся вместе со срезами.

### 3.2. Что снято на время v0

| Маршрут (план 05) | Почему снят |
|---|---|
| `/teach/pisa` | Нет срезов — нечем управлять, и решением этой сессии нет отчёта учителю вообще |
| `/manage/pisa` | Управленческий дашборд строится из данных срезов, которых пока нет |

## 4. Backend: что открывается в v0

Уточняет [план 02 §4](02-moduli-matrix-builder-pisa.md#4-modulespisa--craft-pisa) —
активна только часть `ItemBank` и `Trainers`, без `MediaAiLiteracy`, `Waves`,
`Scoring`, `Readiness`.

```
Modules/Pisa/Features/
├── ItemBank/
│   ├── CreateItem/           # задание собственной разработки       FR-PSA-01
│   └── SearchItems/          # фильтры по направлению/уровню         FR-PSA-01
└── Trainers/
    ├── StartTrainer/         # выбор направления, следующее задание  FR-PSA-02
    ├── SubmitTrainerAnswer/  # ответ → автопроверка                  FR-PSA-04, FR-CMS-02
    ├── ExplainSolution/      # разбор ошибки, подсказки              FR-PSA-04
    └── GetMyTrainerStats/    # личная статистика ученика             новое в v0
```

`ReviewItem` (экспертная рецензия методиста, R-11 плана 02) и
`CalibrateDifficulty` — не в v0, см. открытый вопрос §5-О2.

### 4.1. Данные — лёгкий путь попытки, без сессии урока и без среза

ТЗ уже описывает `item`/`item_bank` как общие сущности банка заданий
([§7.2 ТЗ](../tz/02-tz-nfr-i-priemka.md#72-основные-сущности), «Банк
PISA/MATRIX») — v0 использует их без изменения схемы. Отличие от MATRIX: у
тренажёра нет урока-контейнера и нет `enrollment`, через который в общей
модели идёт `progress` (тренажёр доступен ученику вне курса и вне класса,
см. §1 — «доступно свободно»). Поэтому попытка в v0 связывается напрямую:

```
item (direction, cognitive_process, context, level, expected_time)
 └─ attempt (student_id, item_id, ответ, вердикт, балл, длительность, подсказки)
```

`assessment` / `assessment_run` (сущности среза из ER-схемы ТЗ) в v0 не
используются — они появляются вместе со срезами.

## 5. Открытые вопросы

| № | Вопрос | Рекомендация |
|---|---|---|
| О1 | Кто наполняет банк PISA-заданий до готовой авторской студии? | Как и в MATRIX ([план 06, О1](06-matrix-mvp0-kontent-i-zadania.md#7-открытые-вопросы)) — минимальная форма создания задания для роли `author`/методиста платформы, без визуального редактора; FR-PSA-01 прямо говорит «методистами платформы», не школой |
| О2 | Нужна ли в v0 хотя бы неформальная проверка задания перед публикацией (`ReviewItem`)? | Нет — публикует сразу автор; формальная рецензия (R-11 плана 02) добавляется, когда банк и число авторов вырастут настолько, что качество без контроля начнёт проседать |
| О3 | Задания показываются ученику по параллели (1–11 класс) или без возрастного фильтра, только по выбранному направлению и уровню? | Нужен явный фильтр по параллели: FR-PSA-06 перечисляет метаданные направление/когнитивный процесс/контекст/уровень/время, но не параллель — если не добавить это поле в v0, семикласснику предложится задание для 2 класса. Предлагаю добавить `grade_range` в метаданные задания уже сейчас, до адаптивного подбора (FR-PSA-07) |
