# platform/front — структура Nx-воркспейса

Правило зафиксировано 11.09.2026, до начала вёрстки `apps/admin`. Подробнее
и с примером дерева — [docs/plan/03-design-system.md, §5.0](../../docs/plan/03-design-system.md#50-правило-apps--libscore--libsfeatures--libsshared).

- **`apps/*`** — только конфиг и роутинг. `app.routes.ts` объявляет маршруты
  и ссылается на компоненты, которые физически живут в `libs/features/**`.
  Само приложение (`apps/admin`, `apps/learn`, `apps/landing`) не содержит
  компонентов экранов — только `app.config.ts`, `app.routes.ts`, бутстрап.
- **`libs/core/`** — сквозные не-UI вещи одного приложения: guard'ы,
  интерсепторы, DI-токены конфигурации, сервисы уровня приложения. Не
  компонент и не переиспользуется между приложениями.
- **`libs/features/`** — «умные» компоненты экрана/раздела, на которые
  ссылается роутинг из `apps/*`: по одной библиотеке на раздел (например,
  `features/auth` — экран входа, `features/organizations` — «Школы и
  организации»). Опираются на `libs/shared/ui` за визуальными компонентами.
- **`libs/shared/`** — переиспользуемый слой для всех приложений: `ui-tokens`
  (токены дизайн-системы) и `ui` (немые компоненты на Angular CDK — button,
  status-badge, data-table). Ничего специфичного для одного экрана сюда не
  кладётся.

Перед добавлением нового компонента экрана: если он используется только в
одном разделе — в `libs/features/<раздел>`; если переиспользуется на разных
экранах — в `libs/shared/ui`; если это не UI, а сквозная логика приложения —
в `libs/core`.
